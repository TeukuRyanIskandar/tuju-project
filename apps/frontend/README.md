# @tuju/frontend

TanStack Start 1.x app for **Product A**, built as a **static SPA** (ADR-0005).
SSR capability stays in the box but is deliberately unused for v1 — turning it on
later is an additive change, not a rewrite.

## Shape (traces to ADRs)

- **Static SPA build** — `spa.enabled: true` in `vite.config.ts`. The production
  build prerenders only the root-route shell (`_shell.html`); everything else is
  static assets a CDN serves. No FE server on the request path (ADR-0005).
- **Configurable API base** — `VITE_API_BASE_URL` (see `.env.example`). The FE
  never hard-codes backend URLs (`src/lib/api.ts`); this is the ADR-0005
  migration lever toward a future BFF/proxy.
- **Auth** — the backend owns identity + an httpOnly session cookie (ADR-0005).
  `apiFetch` sends `credentials: 'include'`; the token never touches client JS.
- **Typed data layer** — `apiGet(path, schema)` (`src/lib/api.ts`) throws
  `ApiError` on non-2xx and validates against the `@tuju/contracts` schema in dev
  and test (off in production builds). `src/api/` has the TanStack Query key
  factories and `queryOptions` builders per area; the `QueryClient` lives in the
  router context and loaders use `ensureQueryData`.
- **Tier = show/hide only** — `src/lib/auth.ts` reads `tier` from `/auth/me` for
  presentation. It asks capability questions (`canRunJob`), never compares tier
  names. The backend always re-checks at the enqueue seam; the FE never enforces.
- **Contract seam** — consumes `@tuju/contracts` TS types (e.g. `JobName`), no
  cross-language imports (ADR-0002).
- **Wiring proof** — the `/` route loader calls the backend `/health` (ADR-0010)
  through the configurable base.

## Commands

```bash
pnpm --filter frontend dev        # dev server on :5173
pnpm --filter frontend build      # static SPA bundle (Vite + Start SPA prerender)
pnpm --filter frontend test       # Vitest
pnpm --filter frontend typecheck  # tsc --noEmit
```

`src/routeTree.gen.ts` is generated by the TanStack Router plugin during
dev/build (and via `pnpm --filter frontend generate-routes`); it is gitignored.

## Browser smoke tests

Vitest tests component behaviour with jsdom. Playwright separately tests the
**production static build in Chromium**, with deterministic intercepted search
responses (no running backend, credentials, Docker, or LLM required):

```bash
pnpm --filter @tuju/frontend exec playwright install chromium
pnpm --filter @tuju/contracts build
VITE_API_BASE_URL=http://127.0.0.1:4173/test-api pnpm --filter @tuju/frontend build
pnpm --filter @tuju/frontend test:e2e
```

The suite starts its own static server on port 4173. It checks mouse and keyboard
search, empty results, primary navigation, direct nested links and refresh. Pages
are still placeholders: these are shell/search smoke tests, not evidence of
completed dashboard features. CI runs this suite on PRs and main pushes, uploading
an HTML report and failure traces/screenshots.

The test server mirrors the SPA shell fallback, but does not test nginx itself.
Real-backend browser integration (CORS, cookies and actual search data), mobile
layouts, coverage thresholds and required GitHub branch checks remain separate
follow-ups. For each new screen, add interaction, loading, empty and failure-state
tests in Vitest; extend Playwright for critical user journeys.
