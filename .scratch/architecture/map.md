# Architecture Map — Bursa Platform (Product A)

Label: `wayfinder:map`

## Destination

A locked set of architecture ADRs + a scaffold plan for the Bursa platform — enough that an executor can scaffold the monorepo with nothing left to decide. **Decisions only**: this map resolves architecture questions and records ADRs; the actual scaffold happens in a fresh execution context later.

## Notes

- **Scope: Product A only.** The one-stop dashboard + automated TA/FA + basic IPO/prospectus doc analysis. Products B (financial-products marketplace) and C (power-user deep doc analysis) are considered only as *forces* — the architecture must let them slot in later — but their design is out of scope for this map.
- **Locked stack givens (do not re-litigate):**
  - Frontend: **TanStack Start**
  - Backend: **NestJS**
  - AI module: **Python + LangGraph**
  - Repo shape: **monorepo**
  - Communication between NestJS and the AI module: **queue / messaging** (async). The *specific* broker is an open decision, not a given.
- **Planning-first:** produce decisions and ADRs, not code. Execution is a separate later effort.
- **Skills every session should consult:** `grilling` + `domain-modeling` for decision tickets; `research` for AFK research tickets. Record durable decisions as ADRs under `docs/adr/`.
- **Domain "why":** see the Lean Model Canvas (Bursa/IPO/FCPO intelligence; warm audience of ~500 early adopters).

## Decisions so far

- [Research: message broker options for NestJS ↔ Python job semantics](issues/01-broker-research.md): Decision-grade comparison gathered. Key finding — **BullMQ has official first-party Python bindings**, so Redis+BullMQ interoperates cleanly JS↔Python (no JS-only lock-in). Tentative rec: **Redis+BullMQ** (lowest ops, native progress, idempotent jobs mitigate durability); **RabbitMQ** if delivery guarantees must be contractual. Feeds the broker *decision* in ticket 02.
- [Decide: which message broker / queue between NestJS and the AI module](issues/02-broker-decision.md): **Redis + BullMQ**, native bindings both sides behind a `JobBus` abstraction ([ADR-0001](../../docs/adr/0001-redis-bullmq-nestjs-python-jobbus.md)). Chosen because jobs are idempotent/re-runnable (at-least-once is fine), Redis is acceptable in the stack, and native bindings give clean JS↔Python interop + free progress/retry/DLQ. Guardrails: pin versions + early smoke test, avoid Flows, `JobBus` seam keeps a RabbitMQ migration reversible.

- [Decide: monorepo tooling & layout (TS workspaces + Python coexistence)](issues/03-monorepo-layout.md): **pnpm + Turborepo on Node** for the TS half; **Python is its own uv-managed world** (`services/ai/`) outside the Turbo graph ([ADR-0002](../../docs/adr/0002-monorepo-pnpm-turborepo-python-own-world.md)). Layout: `apps/frontend`, `apps/backend`, `services/ai`, `packages/contracts` (the cross-language schema seam). Bun rejected (NestJS anchors to Node). Services stay cleanly extractable later → satisfies the Products B/C force. Flagged for ticket 08: cross-language **contract drift** is the top structural risk — solve with one schema source generating both TS + Python.

- [Decide: NestJS ↔ AI module transport topology (async-only vs. hybrid sync path)](issues/04-nestjs-ai-contract.md): **Async-only over BullMQ for v1; synchronous path deliberately deferred** ([ADR-0003](../../docs/adr/0003-async-only-transport-sync-deferred.md)). Both TA/FA triggers (user-click + system price-move) enqueue the *same* job; UI streams BullMQ progress events. Deciding reason: the AI module's failure profile makes the queue the right transport (free retry/backoff/DLQ/idempotent re-run) — async is better *because* it fails. Sync added later only if a measured sub-second interactive surface appears (additive FastAPI route, no contract disturbance). Ticket reframed on resolution: the concrete job/result/progress contract belongs to ticket 08; this ticket now owns only the upstream topology decision that shapes 08.

- [Research: market & fundamental data sources for Bursa Malaysia (KLSE)](issues/09-data-source-research.md): Decision-grade comparison gathered ([findings](../../docs/research/0001-bursa-market-data-sources.md)). **Headline: KLSE market data is *licensed* content** — no cheap "personal" vendor tier legally backs a public dashboard. Rec: **EODHD commercial** as anchor (Postgres = system of record), **Twelve Data** as a *deferred, un-persistable* ephemeral live layer (Redis short-TTL only), **scrape/scheduled-ingest** for IPO calendar + prospectus (no vendor API carries those). Fed the data-landing posture in ticket 05. Surfaced pre-contract verification tasks (Bursa Information Services terms, EODHD commercial quote, Twelve Data XKLS terms, FMP/Marketstack symbol probe).

- [Decide: data layer — database, market-data landing, caching](issues/05-data-layer.md): **Postgres + TypeORM; hybrid licensing-driven ingestion; Redis 3-class read-through cache; S3 claim-check for AI artifacts (proxied reads)** ([ADR-0004](../../docs/adr/0004-data-layer-postgres-typeorm-hybrid-ingestion-s3-claimcheck.md)). Postgres = system of record + index; **NestJS sole Postgres writer, Python stateless**; entities in `apps/backend`. Live intraday = deferred Redis-only layer (licence forbids persistence). AI results: Python writes full artifact to **S3**, returns pointer + tiny inline summary over BullMQ; NestJS persists pointer/metadata to Postgres and **proxies** full reads (fetch-time authz; presigned a reversible future swap). Plain Postgres for time-series (no TSDB for Product A). Handoff: exact pointer/summary/progress/failure schema → ticket 08. New infra dependency: object storage → ticket 07.

- [Decide: auth & subscription-tier enforcement](issues/06-auth-tiers.md): **Self-hosted auth in NestJS + centralized, capability-shaped tier authorization** ([ADR-0005](../../docs/adr/0005-self-hosted-auth-nestjs-session-tier-capability-seam.md)). NestJS = identity + session authority; **opaque server-side session in Redis** behind an httpOnly/Secure/SameSite cookie (chosen over JWT for instant revocation). FE ships as a **static SPA, no BFF for Product A** — SSR/BFF deferred (it's a Product B need) but kept a cheap additive migration (opaque Redis session + shared-parent-domain cookie + configurable API base); fixed-price compute noted as a *preference* for ticket 07. Tier gating: single ordinal `tier` field → central **tier→allowed-job-types map**, enforced at the **job-enqueue seam** via NestJS `TierGuard`+`@RequiresJob` decorator (`Reflector`) plus a `JobBus.enqueue` service-level check; system-triggered jobs bypass tier as a trusted internal caller; FE tier = show/hide only. Durable commitment = two invariants (one authz seam; call sites ask `can(user, action)`, never tier names) so permission creep is swap-the-lookup, not a rewrite; CASL is the pre-identified escape hatch for new dimensions (orgs, per-resource sharing). Product B = anonymous path; Product C = a map edit. Scoped out: per-resource row-level authz, pricing/billing.

- [Decide: deployment & runtime shape (local + prod)](issues/07-deployment-runtime.md): **Single EC2 + docker-compose on AWS, externalised RDS + S3, region ap-southeast-1** ([ADR-0006](../../docs/adr/0006-deployment-single-ec2-compose-aws-rds-s3.md)). Prod compute (NestJS + Python worker + **Redis container**, AOF) runs as compose on one **EC2**; **Postgres → RDS**, **object storage → S3** (irreplaceable data off the disposable box; Redis stays on-box, rebuildable). All-AWS, **Terraform**-provisioned; **Singapore** region for the Malaysian audience's interactive latency. **LocalStack replaces MinIO** as the local S3 emulator (supersedes ADR-0004's MinIO; S3 adapter unchanged). Local dev = one `docker compose up` (NestJS + Python + Redis + Postgres + LocalStack), no cloud account. Config = **connection-URL by env** everywhere (never hardcoded hosts) — the tax that makes externalising + later orchestration cheap. **Scale ladder:** workers-wide → scale-up box → **ECS/EKS + ElastiCache** (repackaging stateless containers, not a rewrite); real ceilings are RDS + Redis. **Accepted launch tradeoff:** single-EC2 SPOF (brief reboot downtime; sessions/jobs survive via Redis AOF + idempotency); HA arrives at the orchestration step.

- [Decide: the job / result / progress contract over BullMQ](issues/08-job-contract.md): **Concrete NestJS↔Python contract pinned in `packages/contracts` (single source → TS + Python)** ([ADR-0007](../../docs/adr/0007-job-result-progress-contract-bullmq.md)). v1 = TA + FA as **two independent job names**; doc analysis not forward-declared. **Two ids:** content-derived `jobId` (BullMQ dedup) + per-request `correlationId` (UUID, fan-out to all subscribers on a collapsed job). Generic `JobEnvelope<P>` (correlationId/requestedBy/trigger/asOf) wraps independent per-job payloads. **Progress:** step-based (`stepIndex`/nullable `stepTotal`), no percent, **fixed `phase` enum** per job type. **Result:** `job.returnvalue` (no results queue — S3 holds the blob, Postgres is durable record) = claim-check pointer + **thin stable `summary { verdict, headline, asOf }` (Option A)**; rich detail lives in the **opaque S3 artifact**. **Failure:** two classes — transient (**3 attempts, 5s→15s→30s**) vs terminal (no retry); UI told via `JobFailure { failureClass, retryable, userMessage }`. Retention `removeOnComplete 1h`/`removeOnFail 24h`. `JobBus` signatures pinned both sides. **Ruled out of scope:** the concrete TA/FA indicator/metric set + the artifact's internal JSON shape → separate product effort with partner (contract treats artifact as opaque, so it never disturbs the wire contract).

- [Task: verify Bursa / data-vendor licensing + coverage before contracting](issues/10-data-vendor-verification.md) *(partial — AFK done, ticket still open on HITL)*: **AFK coverage probe resolved** — **FMP DOES cover KLSE** (exchange code `KLS`, `.KL` suffix; price backup only, US-centric fundamentals unverified); **Marketstack does NOT cover KLSE** (its published 70-exchange list omits XKLS) → ruled out as a backup; its free tier is also non-commercial. Confirms EODHD anchor + FMP backup, Marketstack dropped. The three **licensing** facts (Bursa Information Services fee/terms, EODHD commercial quote, Twelve Data XKLS cache/redistribution/latency) remain **HITL** — a precise vendor-contact checklist is recorded on the ticket. **Off the architecture critical path** (ADR-0004 already fixed the data-layer *shape*); deferrable to the execution effort.

- [Decide: CI/CD pipeline shape (two-world build → EC2/compose deploy)](issues/11-cicd-pipeline.md): **GitHub Actions → ECR → manual immutable-tag deploy** ([ADR-0008](../../docs/adr/0008-cicd-github-actions-ecr-manual-deploy.md)). **GitHub Actions** (greenfield on GH; best OIDC-to-AWS docs; GitLab rejected on ecosystem-fit). Contract seam authored **Zod-first** → CI generates TS types + Python **Pydantic** via JSON Schema, runtime validation both ends; **contract-drift gate = check-in generated code, CI regenerates and fails on `git diff`** (the ADR-0002 top-risk guard). **ECR**, images tagged by immutable **git SHA**; **`:latest` forbidden**. **Deploy manual for v1 — CI has zero prod access**; human deploys via **SSM Session Manager** using a **committed compose file pinned to a named tag** (which *is* the prod record), enabling deliberate version choice + rollback (ECR lifecycle keeps ~30 images). **Escape hatch:** SSM Run Command automates later with no change to the tagging model. **Triggers:** PR = checks + drift gate (no deploy); main = checks + push images; **tag `v*`** = release notes from **Conventional Commits** → GitHub Release + version-tag images. Two build worlds run as separate parallel jobs (Turbo cache for TS; uv for Python outside the Turbo graph). Soft coordination with ticket 12 (consumes its secret store). No new fog.


- [Decide: secrets management (store + rotation across three services)](issues/12-secrets-management.md): **gitignored `.env` for dev, SSM Parameter Store SecureString for prod, fetch-on-boot injection** ([ADR-0009](../../docs/adr/0009-secrets-management-env-dev-ssm-prod-fetch-on-boot.md)). Prod secrets live only in **SSM + KMS** (free SecureString; Terraform provisions names/paths, values out-of-band so never in TF state); containers **fetch-on-boot via the EC2 instance role** (no static creds, nothing on disk) and export env vars, so the ADR-0006 connection-URL-by-env invariant holds unchanged (SSM is just the prod *source*). Local dev = `.env` gitignored + committed `.env.example` of fake values; **no real secret ever committed or needed locally** (fixtures-first, per the dev-data-posture effort). Enforcement = **gitleaks** gate on the ADR-0008 PR lane. **Rotation: none for v1** — manual replace-and-redeploy (RDS pw rotated in the same window), consistent with the single-EC2 SPOF; **AWS Secrets Manager (managed RDS rotation) is the deferred escape hatch** at scale, a swap-the-source change, not a rewrite. Closes the soft coordination with ticket 11. No new fog.


- [Decide: observability & logging strategy across the three services](issues/13-observability-logging.md): **Structured JSON to stdout; CloudWatch + tracing deferred as cheap additive steps** ([ADR-0010](../../docs/adr/0010-observability-stdout-json-cloudwatch-deferred.md)). Both NestJS + Python emit **structured JSON to stdout only**; Docker `json-file` driver captures on-box (read via `docker logs`/SSM). **No CloudWatch for v1** — logs disposable-with-the-box (ADR-0006 posture; Postgres/RDS is the durable record). Invariant: **app owns content (JSON), runtime owns transport (driver)**, so enabling CloudWatch later = swap `json-file → awslogs` + a Terraform log group + one line on the ADR-0009 instance-role policy, **zero app-code change**. **`correlationId` (ADR-0007) is a mandatory log field on both services** — the cross-service stitch key (NestJS stamps from request + passes in `JobEnvelope`; Python stamps every line off the envelope). Metrics/health kept lean: `/health` liveness endpoints (compose now, ECS/ALB later) + queue/job/DLQ via **BullMQ introspection** through a **Bull Board** route; **no metrics backend**. **Tracing rejected for v1** (not just deferred) — a 3-known-hop path gains little over correlationId-correlated logs; OTel SDK+Collector+X-Ray is the additive path if a real latency mystery appears, and the mandatory correlationId field means it's not a re-instrument. No new fog.


- [Decide: per-service testing strategy (three services + the contract seam)](issues/14-testing-strategy.md): **Per-service layers + per-world runners + testcontainers at the seams + contract goldens** ([ADR-0011](../../docs/adr/0011-testing-strategy-per-service-testcontainers-contract-goldens.md)). **Layers:** unit + contract launch-required on all three services; integration launch-required only on the two highest-risk seams (JobBus enqueue→process→result incl. failure/retry, and NestJS→Postgres sole-writer path); **frontend e2e deferred** post-launch. **Runners — home turf:** Jest (NestJS), Vitest (TanStack Start FE), pytest (Python, separate CI job outside the Turbo graph); single-runner-everywhere rejected. **Contract testing:** ADR-0008 drift gate (static) **+ runtime golden fixtures in `packages/contracts`** both sides validate (Zod / generated Pydantic) — catches type-valid-but-wrong-shape payloads the gate can't. **Queue/DB:** mock at unit; **real infra via testcontainers at integration** (Redis+Postgres+LocalStack = the ADR-0006 compose stack), chosen because ADR-0007 retry/DLQ + ADR-0004 sole-writer are exactly what mocks get wrong (Docker-in-CI now a hard integration-lane requirement). **Fixtures boundary:** this ticket owns contract/structural fixtures + the harness; the **separate dev/prototype data-posture effort owns market-fixture sourcing + licence posture** (interface = "fixture file at a known path"); TA/FA market-realism tests **skippable-with-a-marker** until that effort delivers (soft, non-blocking). No new fog. **Last frontier ticket → destination reached.**
