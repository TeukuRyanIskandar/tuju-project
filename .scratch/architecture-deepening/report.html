tuju-project: deepening opportunities

Scope came from commit churn since August. The hottest areas were apps/backend/src/ingestion, data/*, stocks, jobbus, services/ai/src/tuju_ai (handlers, prospectus/, llm/) and packages/contracts. The frontend apiGet(path, schema) seam is already deep, so it is not covered here.

module seam leak deep module

Bugs found along the way

I verified each one against the source. They also show where shallow modules let bugs collect in the code that calls them.

  • TA/FA enqueue throws. JobBus.deriveJobId builds ta:SYM:1D:2026-09-29T05, which has 4 colon parts. BullMQ 5's validateOptions throws "Custom Id cannot contain :" on any id that contains : and doesn't have exactly 3 parts. As a result, POST /analysis and every KLCI enqueue fail. apps/backend/src/jobbus/job-bus.service.ts:189
  • Integration tests run in the wrong lane. 9 testcontainer specs named *.int.spec.ts (about 4.7k lines) match the unit regex .*\.spec\.ts$ and never match test:int's .int-spec.ts. apps/backend/jest.config.cjs:12
  • AI summaries stay invisible for about 24h. AnnouncementSummaryStore writes aiSummary but invalidates no cache. Its jobs are enqueued after the nightly sweep, so readers keep getting the 24h-TTL cached copy.
  • Wrong derivedFrom. whatToWatch.derivedFrom lists 4 sections, but the reduce step is fed 6, including lock-up and related-party. services/ai/src/tuju_ai/prospectus/analysis.py:447
  • TA/FA ignore LLM config. They read os.environ directly, hardcode ceiling_usd=0.10, and include a production branch if api_key == "test-key-for-testing". ta_fa_analysis.py:276–284, 432, 565

Problem. A job family's identity (bull id, result id, store prefix, Python prefix) is spread across about 9 shallow modules. The broken TA/FA bull id stayed hidden because the parsers are tested on their own while the call site is not.

Solution. Add one JobFamily per job name that owns its id formats, result landing and failure. JobBus dispatches each result to exactly one family, and TA and FA merge into one parameterised family.

  • Delete 2 pass-through modules

  • getQueue() leak removed from ingestion

Top recommendation

01: the Job family module

This is where the most churn and the only production-breaking bug meet: TA/FA enqueue is broken today because job identity is spread across 9 shallow modules and the call site is never tested. A Job family module fixes the bug where it lives, makes the JobBus seam real with a second adapter, and gives #4 (cache) and #8 (Stock analysis) a single land() to hook into. Before you start, rename the 9 *.int.spec.ts files so the integration tests that would catch this kind of bug actually run.
