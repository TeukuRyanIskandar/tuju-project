# Free Tier Map — Bursa Platform (Product A)

Label: `wayfinder:map`

## Destination

A **set of handoff specs** for the Product A free tier (backend only), one per feature area, each specific enough that an agent can break it into build tickets and implement it with nothing left to decide. The specs must support a **private demo prototype** for partners and early investors.

> the handoff specs are written under [`.scratch/free-tier-specs/`](../free-tier-specs/README.md)
> (six specs + an index/README with build order, candidate ADRs, and deferred fog).
> Only the still-fog areas below (charting-data endpoints, anonymous rate-limit posture,
> watchlist+accounts behaviour, forward earnings calendar) remain unspecified — each
> returns as its own effort when sharp. Ticket 06 (real-price quote) stays open in the
> background but blocks nothing (real prices are a later adapter swap).

## Notes

- **Planning only.** Resolve decisions; the specs are written at the end (via `to-spec`) and built by separate execution efforts.
- **Backend only.** Frontend/UI (incl. the charting component) is out of scope; backend endpoints that *feed* charts are in scope.
- **Fixed inputs (do not re-decide):** ADR-0001…0011. Especially ADR-0004 (NestJS sole Postgres writer, Python stateless, 3-class Redis cache), ADR-0005 (free tier = no user-triggered AI jobs; anonymous path; `can(user, action)` seam), ADR-0007 (job contract).
- **Demo audience = private** (partners, early investors). Personal/free vendor tiers and captured fixtures are acceptable *if research confirms the licence allows a private demo*; nothing goes public until the production licensing work ([vendor verification task](../architecture/issues/10-data-vendor-verification.md)) is done.
- **Freshness:** end-of-day is the baseline; **delayed intraday is acceptable**.
- **Accounts:** browsing is anonymous; sign-up only for account-bound features (watchlist).
- **Absorbs the "dev/prototype data posture" effort** that the [architecture map](../architecture/map.md) spun out but never charted.
- **Spec units (provisional, split further if needed):** data ingestion (shared, blocks the rest) · search + stock page · announcements + news + corporate events · IPO calendar · market overview · watchlist + accounts · screener.
- **Skills every session should consult:** `grilling` + `domain-modeling` for grilling tickets; `research` for research tickets (findings land in `docs/research/`); `to-spec` when writing the final specs.
- **Research findings live on unmerged branches** (`research/demo-market-data`, `research/disclosure-news`, `research/screener-indicators`, each with a worktree at `..\tuju-research-<name>`). Until merged, read them with e.g. `git show research/disclosure-news:docs/research/0003-disclosure-and-news-sources.md`.
- **Feature scope (user, charting session):** all of: search, stock page, announcements, news, IPO calendar, market overview, watchlist, basic screener, Shariah flag, corporate-actions calendar, quarterly-results calendar, substantial-shareholder/director dealings. In-app charting is wanted later (backend data for it is in scope).

EODHD covers every free-tier data class once licensed ([findings](../../docs/research/0002-demo-market-data-sources.md), branch `research/demo-market-data`).
- [Research: Bursa public-disclosure, Shariah-list and news sources](issues/02-disclosure-and-news-sources.md): **Bursa's site 403s all automated access**; aggregators (i3investor, KLSE Screener) are reachable and partly structured but unlicensed, so demo-snapshot only. Production needs a licensed Bursa disclosure feed. Shariah list = SC PDF twice a year (manual ingest). News = RSS headline + link. IPOs = curated manual entry ([findings](../../docs/research/0003-disclosure-and-news-sources.md), branch `research/disclosure-news`).
- [Research: screener fields and indicator computation for KLSE](issues/03-screener-and-indicator-data.md): Baseline = **KLSE Screener's filter set**. **Filter our own Postgres** (EODHD Screener has 14 fields, no P/E/ROE/NTA/Shariah) and **derive ratios in-house**. Indicators via **TA-Lib in the Python worker** as a system job (`pandas-ta` upstream gone). Basic demo filter set + technical extension defined ([findings](../../docs/research/0004-screener-and-indicator-data.md), branch `research/screener-indicators`).
- [Decide: demo data posture](issues/04-demo-data-posture.md): **Synthetic-but-labelled prices; real public reference + disclosure data; everything behind a source-adapter seam.** No self-serve vendor tier legally shows real KLSE prices to outside partners/investors and a permitting licence (EODHD Custom ≥US$399/mo + agreement, Enterprise US$2,499/mo) isn't justified for a pre-revenue demo — the pitch showcases the analysis/AI engine, not price accuracy. Per class: reference data real (public); **EOD/intraday/index synthetic, labelled "illustrative"**; **fundamentals synthetic and co-generated with prices so all price-derived ratios reconcile (decision A1** — real fundamentals + fake prices = misleading nonsense, rejected); announcements/corporate-events = unlicensed aggregator **snapshot, demo-only**; news = RSS **headline+link only**, ticker-tagged by us; Shariah = SC PDF manual twice-yearly; IPOs = manual + stored PDFs. **Licence boundary (decision B):** synthetic may stay at public launch (relabel or swap to licensed adapter); **aggregator announcements/events MUST be purged + re-sourced from a licensed Bursa feed** (architecture ticket 10) before any public exposure; news stays headline+link. Real prices are a later **adapter swap**; ticket 06 keeps chasing a quote in the background but nothing blocks on it. **No data class dropped.** Unblocks [ingestion pipeline shape](issues/07-ingestion-pipeline-shape.md) with the concrete adapter list + synthetic co-generation constraint.

- [Decide: how the free tier and the demo showcase AI capabilities](issues/05-ai-showcase.md): **Shape B only** — system-generated AI content via ADR-0005's trusted system-caller path (no user-triggered jobs; **ADR-0005 unchanged**). A rejected (**no paid features exist yet** — demo accounts would showcase vapour); C rejected (per-user quota is needless for a private demo). Showcase = a **set**: two shallow *now* — **daily market brief** (on synthetic "illustrative" prices; must not dress fake numbers as market truth) and **announcement summaries** (on the demo-only aggregator snapshot) — plus one **deep, deferred** artifact: the **IPO prospectus "at-a-glance"** (sections: offer / business / financials trend / ranked risks / what-to-watch), the only artifact on real licence-safe data (stored PDFs). Deferred for its ingestion engineering. Spawns [long-document ingestion research](issues/08-long-document-ingestion.md) → [prospectus at-a-glance decision](issues/09-prospectus-at-a-glance.md).
- [Research: best-in-class ingestion of 500–1000 page documents](issues/08-long-document-ingestion.md): **Skip classic RAG.** For a handful of prospectuses that each fit a modern context window, recommend **layout-parse-to-sections (Docling, pure-Python/MIT) → long-context per-section prompting with prompt caching**, exploiting the regulated Bursa/SC section skeleton to deterministically route the four regulated outputs (no embeddings/reranker/vector store); what-to-watch is a reduce over the rest. Parse persisted as an S3 claim-check (ADR-0004). Baseline/fallback = whole-doc long-context prompting (Gemini 2.5 1M window fits 1000pp). Start on Gemini 2.5 Flash (~<$0.20/doc est.), A/B against Pro/Claude for financials + risk ranking. RAPTOR / contextual-retrieval deferred until corpus outgrows one context window ([findings](../../docs/research/0005-prospectus-ingestion.md), branch `research/prospectus-ingestion`). Unblocks [prospectus at-a-glance decision](issues/09-prospectus-at-a-glance.md).
- [Decide: ingestion pipeline shape](issues/07-ingestion-pipeline-shape.md): **Ingestion runs in a dedicated second NestJS process (d-process, same `apps/backend` codebase/entities/migrations), `@nestjs/schedule` crons living only in the worker. Python is NOT in the free-tier ingestion path.** Indicators computed **in the NestJS worker in TypeScript (`trading-signals`)** over synthetic prices — a **deliberate override of research 03's TA-Lib-in-Python** (precision is meaningless on synthetic data; keeps the whole demo ingestion one-language and leaves **ADR-0007 untouched**). Vendor technical endpoints rejected as the screener engine; indicators stay an in-house derivation in demo AND paid tiers (paid = same derivation over real licensed prices, the EODHD adapter swap). Six ticket-04 adapters confirmed behind the seam. Cadences: nightly synthetic EOD+fundamentals → nightly indicator snapshots (ordered) → **5-min** synthetic intraday replay to Redis-only (never Postgres) → 15–30-min RSS → **static** disclosure snapshot (no live re-scrape) → manual Shariah/IPO. Backfill = **3 years** for both prices and quarterly fundamentals (one coherent, reconciled timeline; warms SMA-200, satisfies YoY growth). Production scaling deferred behind the seam (JobBus fan-out for intraday; optional TA-Lib engine swap). Flags a candidate ADR (worker + TS-indicator override) for `to-spec` time.

- [Decide: the IPO prospectus "at-a-glance" artifact](issues/09-prospectus-at-a-glance.md): **Adopts research 08's Docling parse-to-sections → long-context per-section (Flash first, A/B Pro/Claude on financials+risk) unchanged.** New additive **`analyze-prospectus`** job on the `analysis` queue, `ProspectusPayload = { prospectusId }`, Docling parse persisted as S3 claim-check, runs on the **Python worker** (first free-tier Python AI job; no conflict with ticket 07 which excluded Python from *synthetic-price* ingestion only). **Wire contract:** add **`trigger: 'system'`** to the enum (additive — also serves the two shallow showcase artifacts); rich 5-section output is **opaque JSON in the S3 artifact**; thin wire summary is **verdict-less `{ headline, asOf }`** (headline = "what to watch"); provenance `source: real`. **Artifact = the 5 sections (offer / business / financials trend / ranked risks / what-to-watch) + 2 Bursa insights: Shariah status + cornerstone investors** (both clean data); **peer valuation deferred** (would rest on synthetic demo prices). **Corpus = 3 manually-downloaded PDFs, no live scraper** (automated fetch pushed to the licensed-feed boundary); 3 real 2025 Bursa company IPOs (IAB, LSH, Fibromat) downloaded to `demo-corpus/prospectuses/`. Budget ~$2/doc. Flags additive ADR-0007 amendment for `to-spec`.

- [Decide: the free-tier domain model](issues/10-free-tier-domain-model.md): **Company (issuer) split from Instrument (tradable line); analysed universe = ordinary shares of Main+ACE only** (REITs/ETFs/warrants excluded from analysis but IPO calendar may list them). **Provenance = lineage, not a per-row `source` column:** an `IngestionRun` knows its adapter + provenance class (`synthetic`/`aggregator`/`real`), every sourced row FKs `ingestionRunId`; decision-B purge deletes rows from aggregator/synthetic runs (lineage survives usefully into prod — no go-live tech debt). A1 co-generation = a `SyntheticRun` carries seed+params, price bars + fundamentals FK to it (regenerable/purgeable unit); **shares outstanding held constant**. Financials split: **`QuarterlyFinancials`** (source-of-truth timeline, 3-yr) + derived **`FundamentalsSnapshot`** (TTM rollup); **dividends are `CorporateAction`s** (single source for calendar + DY). **Bursa `Sector`** reference entity. **Ratios defined once** (P/E null on TTM-EPS≤0 loss-making; DY = TTM dividends; P/NTA with generated intangibles so ≠ P/B; ROE on average equity; D/E = borrowings; PSR; YoY = same-quarter-prior-year, consecutive = N positive-YoY quarters). **`IndicatorSnapshot`** = per-symbol latest (not a series; 52-wk hi/lo via SQL window). **`ShariahStatus`** history table; **Watchlist** = User→Watchlist→Instrument (only account-bound entity). All terms in `apps/backend/CONTEXT.md`. Graduates the per-feature spec areas: [search + stock page](issues/11-search-and-stock-page-spec.md), [screener](issues/12-screener-spec.md), [announcements + news + events](issues/13-announcements-news-events-spec.md), [market overview](issues/14-market-overview-spec.md).

- [Spec: screener (free-tier backend)](issues/12-screener-spec.md): **A pure-SQL projection over already-ingested Postgres, no JobBus.** Filter set = research 03's demo baseline mapped to ticket-10 entities — universe (board Main/ACE, Bursa `Sector` FK, latest-`ShariahStatus` boolean), price/liquidity/market-cap, valuation (P/E, DY, P/NTA), quality (ROE, D/E, profitable-years), growth (YoY profit, consecutive-growth quarters), plus a **technical extension** (RSI-14, above-SMA-50/-200 flags) reading the nightly `IndicatorSnapshot` — **stochastic deferred** (outside ticket-10's fixed indicator set). **Ratios are read, not computed at query time**: materialised onto `FundamentalsSnapshot`/`IndicatorSnapshot` by ticket 07, so the screen is plain indexed SQL over ~1,000 rows joining the latest derived rows. **Null handling** relies on SQL NULL semantics — loss-maker P/E (ticket 10) is absent from any P/E band for free, NULLs sort last. Result row carries per-class **provenance** (IngestionRun lineage) for the illustrative label; default sort `%change` desc; offset/limit (default 50, max 100) with total count; no vendor row cap (we own the rows). **Cache = ADR-0004 class 2** (aggregated view, keyed by normalised params, invalidated on nightly ingest). Endpoint `GET /screener` (anonymous) + `GET /screener/fields`. Saved-screens/screen-to-watchlist deferred to watchlist area; anonymous rate-limit posture stays the cross-cutting open question. No new fog, no ticket invalidated; ready for `to-spec`.

- [Spec: market overview (free-tier backend)](issues/14-market-overview-spec.md): **Three panels — movers, index, sector performance — over ticket-10 entities + ticket-07 cadences; introduces one new entity pair behind the seam.** **Movers = whole analysed universe, no liquidity/market-cap floor (option A, simplest)**; gainers/losers/actives by `%change`/volume, precomputed into the 5-min Redis intraday replay (Redis-only), EOD-close fallback outside hours. **Index panel = new stored `MarketIndex` + `IndexLevel`** (a FBM KLCI analogue + per-`Sector` indices; daily level series parallel to price bars, `IngestionRun` provenance), **cap-weighted**, computed nightly to Postgres + live level in the 5-min Redis replay, all **behind a new `IndexAdapter`** on the ticket-04 seam — demo cap-weights synthetic constituents (`synthetic`), production ingests a licensed feed or recomputes over real prices (identical entities/endpoints; **whether "FBM KLCI" may be shown in prod deferred to the architecture map's [vendor task](../architecture/issues/10-data-vendor-verification.md)**). **Sector performance = reads the per-`Sector` `IndexLevel`s** (same machinery, cap-weighted). **Cache = class 3 for anything intraday-live (Redis-only), class 2 for EOD-derived/stored series** — matches ticket 07's "intraday never touches Postgres". Endpoints `GET /market/{movers,indices,indices/:id/series,sectors}` (anonymous). **Adds `MarketIndex`/`IndexLevel`/`IndexAdapter` to the shared model + glossary** (ticket 10 stays closed; this spec owns the addition for `to-spec` to fold in). No ticket invalidated; anonymous rate-limit posture stays the cross-cutting open question; ready for `to-spec`.

- [Spec: announcements + news + corporate events (free-tier backend)](issues/13-announcements-news-events-spec.md): **Pure read projection over ingested Postgres, no JobBus; four read models (`Announcement`, `NewsArticle`, `CorporateAction`, `QuarterlyFinancials`) + two derived calendars, all `aggregator`-class (decision-B purge target).** **Categorisation:** a **stable internal `AnnouncementCategory` enum** (10 values: financial-results, entitlement, shareholding-change, general, additional-listing, meeting, circular, annual-report, listing, other) that the aggregator adapter maps its labels onto — Bursa's own taxonomy is `[UNVERIFIED]` (site 403s), so a licensed feed later re-maps to the *same* enum; announcements carry title/filedAt/sourceUrl/provenance, **no attachment bodies** (Bursa detail 403). **Owns the `Announcement.aiSummary` field** (ticket-05 announcement-summaries showcase lands here; inherits `aggregator` provenance; generation job is 05/09's). **News ticker-tagging:** headline+link+source+publishedAt only; **conservative whole-word alias match** (`shortName`/`fullName`/curated `Company.aliases`) via a `NewsArticleTag` M2M, multi-company allowed, no-match = market-level news, deterministic (not AI). **Calendars:** corporate-actions over `CorporateAction` keyed on **`exDate`** (single source with DY); results calendar over `QuarterlyFinancials` is **backward-looking = when filed** — **forward earnings calendar out of scope** (no licensed KLSE source). **Dealings feed = a view of `Announcement` where `category=SHAREHOLDING_CHANGE`**, list-level fields only (**structured buyer/volume/price deferred** — needs licensed structured feed). Endpoints all anonymous, **class-2 cache**; provides ticket 11's `/stocks/:code/{announcements,corporate-actions}`. Additive to ticket-10 model (`AnnouncementCategory`, `NewsArticleTag`, `Company.aliases`, two derived calendars). No ticket invalidated; ready for `to-spec`.

- [Spec: search + stock page (free-tier backend)](issues/11-search-and-stock-page-spec.md): **Pure read projection over ingested Postgres, no JobBus; endpoint shape B.** Search = **trigram (`pg_trgm` GIN index) fuzzy match** over `Instrument` code/short/full name, ranked exact-code → code-prefix → name-prefix → trigram-similarity — **correct at demo *and* production scale** (universe bounded by the exchange at ~1k–low-10k rows; `pg_trgm` scales to millions, so row count never bites; **the only search scaling lever is request volume**, i.e. the cross-cutting anonymous rate-limit posture, not the engine — no external search engine, behind a swappable `InstrumentSearch` seam). Stock page = **shape B**: bounded core `GET /stocks/:code` (Instrument+Company+Sector identity, latest `FundamentalsSnapshot`+read ratios, latest `IndicatorSnapshot`, latest `ShariahStatus`) **plus separate paginated** `GET /stocks/:code/{announcements,corporate-actions}` reading **ticket-13's read model scoped to one company** (announcement taxonomy + AI-summary field owned by 13, referenced not redefined). Provenance = ticket-10 `IngestionRun` lineage join, grouped per data class (identity/Shariah `real`, fundamentals/ratios/technicals `synthetic`, disclosures `aggregator`) → per-block "illustrative" label. Cache: `/search` + `/stocks/:code` + list endpoints all **class 2** (EOD-derived, invalidated on nightly/disclosure ingest); header close/%change is EOD-snapshot (a **live intraday header quote deferred** to a possible class-3 field later, like market-overview movers). Charting/OHLC series stays fog; watchlist add-from-page deferred. No new fog, no ticket invalidated; ready for `to-spec`.
