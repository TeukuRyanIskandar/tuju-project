================================================================================
                              THE PROBLEM
================================================================================

Current state (spec-06):
  - Prospectus parse: Docling full-document layout ML → 10–12 min per PDF
  - Docker image: ~2.5 GB (torch wheels dominate)
  - Corpus scale: 3 PDFs = 30 min; 20 PDFs = 3+ hours (unacceptable)

Why it matters:
  - Blocks dev iteration ("parse takes longer than coding")
  - Impossible to expand corpus without batch-window explosion
  - Docker image size = deployment friction

================================================================================
                             THE SOLUTION
================================================================================

Two-phase parse architecture:

  Phase A (PyMuPDF, ~5–15 sec):
    - Extract headings via native PDF TOC (true hierarchy levels)
    - Extract text blocks in reading order + page numbers
    - No ML, no torch (pure C binding)

  Phase B (Camelot, ~10–30 sec on financials pages only):
    - Only target the located financials section's page range
    - Extract tables with lattice→stream fallback
    - Splice into parse, deduplicate vs. raw text
    - If financials not located, skip entirely

  Total: ~1–2 min per PDF (5–10x faster than Docling)
  Docker image size: ~350 MB (7x smaller)

Model switch:
  - Gemini 2.5 Flash (paid) → openrouter/free (router, $0/call)
  - Sufficient for showcase; no credits needed

New sections (materiality for Bursa retail investors):
  - Lock-up / moratorium arrangements (founder lock-in periods)
  - Related-party transactions (governance risk)
