## Task

Scaffold the Python AI worker — a stateless job consumer.

- `services/ai` as a **uv**-managed Python project (ADR-0002), outside the Turbo graph.
- **BullMQ Python bindings** (ADR-0001): a worker that consumes the stub job name from
  ticket 03's JobBus over Redis (connection URL by env, ADR-0006), emits step-based
  progress (ADR-0007), and returns a `job.returnvalue` (claim-check pointer + thin
  summary) — with a stub S3 write to LocalStack (ADR-0004/0006).
- **Contract models:** import the generated Pydantic v2 models from ticket 02;
  validate the incoming `JobEnvelope` and outgoing result against them (runtime
  conformance, ADR-0011).
- **Stateless reader** (ADR-0004): if it reads Postgres, read-only; never writes
  (NestJS is sole writer). A stub read is fine.
- **S3 claim-check** (ADR-0004): write a placeholder artifact to S3 (LocalStack
  locally), return the pointer over BullMQ.
- **LangGraph**: a trivial graph stub (no real TA/FA logic — that's a later feature
  effort, explicitly out of scope per the architecture map).
- **Logging** (ADR-0010): structured JSON to stdout; stamp `correlationId` from the
  envelope on every line.
- **Tests** (ADR-0011): **pytest**; a unit test (fixture DataFrame / envelope parse)
  + integration placeholder marked to run against testcontainers.

## Done when

`uv run` boots the worker; it consumes the stub job, writes a placeholder artifact to
LocalStack S3, returns a valid pointer+summary that Pydantic accepts; pytest unit test
passes.
